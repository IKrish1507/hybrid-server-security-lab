# DNS: a parent zone on Windows, a delegated child zone on BIND

## Design

| Zone | Authoritative server | Records |
|---|---|---|
| `corp.lab` | Windows Server 10.0.2.2 | `ns`, `mail`, `site` (A), `www` (CNAME to `site`), delegation for `it` |
| `it.corp.lab` | CentOS BIND 10.0.2.1 | SOA, NS, MX, `ns`, `site` (A), `www` (CNAME) |
| `2.0.10.in-addr.arpa` | both (separate labs) | PTR records for 10.0.2.x |

Each server is authoritative only for its own zone. The Windows parent zone has a delegation that points `it.corp.lab` at the BIND server, so a client asking Windows for `www.it.corp.lab` is referred to CentOS.

## What I did

**Windows Server.** Added the DNS Server role, created a primary forward zone with dynamic updates off and a reverse zone for network 10.0.2, added the host records and tested with `nslookup`. The default `nslookup` server is the internet-facing adapter, so I switched it to `server 10.0.2.2` before testing. Lookups for the child zone only worked after I added the delegation.

**CentOS (BIND).** Installed `bind`, changed `listen-on` and `allow-query` in `/etc/named.conf`, defined the forward and reverse zones, built the zone files from `named.empty`, set the group to `named` so the service can read them, validated with `named-checkconf` and `named-checkzone`, opened DNS in firewalld and tested with `dig`.

**Clients.** On CentOS, `/etc/resolv.conf` is generated by NetworkManager, so name servers, search domains and `dns-priority` are set in the connection profile, not in resolv.conf. On Windows, the adapter with the lowest `InterfaceMetric` wins, which I checked with `Get-NetIPInterface` and `Get-DnsClientServerAddress`.

## Things that break DNS quietly

- A missing trailing dot on SOA and NS names makes BIND append the zone name again (`ns.it.corp.lab.it.corp.lab`).
- A stray space inside the quoted reverse zone name in `named.conf` creates a zone nobody queries.
- The SOA serial must go up on every change, or secondaries and caches keep the old data.
- Zone files owned by `root:root` with mode 640 can't be read by `named`.

## Security notes

- `allow-query { any; }` is fine on an isolated lab network. On a real network, restrict queries to internal subnets and disable recursion on authoritative servers to avoid becoming an open resolver.
- Zone transfers should be limited with `allow-transfer` to known secondaries only.
- Always validate first: `named-checkconf && named-checkzone ...` before `systemctl reload named`.
